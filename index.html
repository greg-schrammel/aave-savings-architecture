Architecture walkthrough

How the savings simulator is put together

A one-screen Expo app that projects what a savings plan grows to at Aave's stablecoin rate. Nearly every pixel that moves is driven on the UI thread, and React's job is mostly to lay things out once. This page goes through it from the top down: the threads, boot, the screen, then each subsystem.

01Big picture

Roughly 12k lines in src/, one screen, three trays, and a native glass view written for both platforms.

The stack

Expo 58 · RN 0.88

Built from source with Hermes V1, because the RN patch has native hunks. Uses prebuild with config plugins.

Reanimated 4 + Worklets

Shared values and worklets drive almost every animation, so motion never waits on the JS thread.

Skia 3.8

Draws the chart, the tooltip, the axis and the "?"/Reset morph. Labels are shaped Regola paragraphs.

Gesture Handler 3

The v3 hook API (usePanGesture, useManualGesture) for scrubbing, the glass and the menu.

TrueSheet

Native bottom sheets for the three trays. Heavily patched.

PlainText

Draws single-run labels as native text instead of RN <Text>, which is cheaper.

nano-icons

MMKV · nitro-haptics

MMKV stores the theme, the last simulated plan, the rate choice and the saved rate. Haptics fire on the UI thread when called from a worklet.

02The three-thread rule

The idea the rest of the codebase follows: JS lays out, the UI thread blends, native draws.

A gotcha that bit us: a worklet that calls a plain JS function crashes the app with Tried to synchronously call a Remote Function. Anything a worklet calls must itself be a worklet ("worklet";), or be computed ahead of time on JS. The EdgeFade launch crash was a .map inside a useDerivedValue, so its stops are now precomputed constants.

03Boot sequence

The splash stays up until the screen can draw its finished first frame.

  1. index.js: with Worklets bundle mode the same bundle is also evaluated on the UI runtime, so the app registers itself only on the React Native runtime (__RUNTIME_KIND === 1).
  2. App.tsx module scope: preventAutoHideAsync(), preloadTypefaces(SKIA_TYPEFACES) and prefetchAaveRate(). The network request overlaps the first render.
  3. App waits for the Skia typefaces, capped at 1500 ms so a stuck font load can't keep the splash up. The hero falls back to a system face.
  4. Once ready it hides the splash and calls HermesInternal.ttiReached(). That ends Hermes's allocate-in-old-gen startup mode (withHermesOldGenBeforeTti.ts).
  5. Tree: QueryClientProvider → GestureHandlerRootView → SafeAreaProvider → ThemeProvider → SavingsScreen. Once the screen shows, warmUpGlassLens() runs on an idle callback so the first glass menu doesn't pay to compile the lens shaders.
  6. The Add Money tray mounts its content 1.5 s after launch, on an idle callback, so opening it later costs only the native present. The info trays mount their content when they open.

On Android, several config plugins cut cold-start time: React starts loading from Application.onCreate, native libraries preload on idle cores (worklets alone take about 11 ms on the Redmi), EmojiCompat is removed (about 6 ms on the main thread), and a baseline profile AOT-compiles the cold-start path. The numbers live in .claude/skills/performance/history.md.

05Data & maths

projection.ts

src/projection.ts · plan.ts

360 months, computed once per plan and rate. The APY is already a compounded annual yield, so a year grows by exactly 1 + APY. Growth uses L = ln(1 + APY) via Math.log1p. Recurring deposits (monthly, weekly or daily) sum as a geometric series: deposit k has grown e^(L(t − kp)). amountsAtMonth() splits any month into deposited and earned. plan.ts holds the base rate, default plan, deposit caps and rate choices. savedSimulation.ts saves the last simulated plan (deposits and frequency, not the rate) and the rate choice in MMKV; anything this build couldn't have saved (over a cap, unknown frequency, bad JSON) is no plan. A restored plan shows as set up but skips the growth wave and haptics.

Defaults: BASE_APY = 6%, $500 per month. Caps are $100k recurring and $10M one-off.

rate/

aaveRate.ts · useAaveRate.ts

Calls Aave's GraphQL API (api.v3.aave.com) and averages the stablecoins' recent supply APY. It needs most of a quarter's daily samples, so a gap can't pass for an average. GHO is left out because it earns by staking. Any unusable reserve throws, so one bad coin can't skew the mean. An average over 30% (MAX_PLAUSIBLE_APY) is a broken feed and counts as unusable. The rate is saved in MMKV for 30 days and refreshed hourly and when the app returns to the foreground (focusManager on AppState). With nothing saved, the label is a skeleton for up to 2.5 s (RATE_WAIT_CAP_MS, isLate), then the base-rate projection shows until Aave answers.

format.ts

src/format.ts

Money formatting for en, pt and es. On Android, Hermes builds an ICU matcher for each Intl.NumberFormat (about 8 ms each on the Redmi). So one probe reads the locale's number shape and the formatters are plain JS. Shapes the probe can't reproduce, like lakh grouping, keep Intl. Axis labels use two significant digits ($5.8k), and the tooltip uses two decimals in a unit.

i18n/

en.ts · pt.ts · es.ts · locale.ts

The locale resolves once per launch; iOS restarts the app when the language changes. interpolate and interpolateParts fill templates, keeping styled <Text> parts. Hermes has no Intl.PluralRules, so a one/other rule covers all three languages.

06Hero amount

HeroAmount.tsx · heroLayout.ts · EarnedLine.tsx

The balance is a fixed set of 20 slots, mounted once: $, twelve digit places (units first), four group separators, the decimal separator and two cents digits. A new amount costs no render.

  • Keyed by place from the units, so a digit keeps its slot as the number grows a place.
  • Digits roll in the direction the amount moved. Slots that appear or go slide in from the front, and a slot that goes is gone in the first third.
  • While the chart is scrubbed, the scrubbed bar's amount shows at once so it keeps up with the finger. The first bar rolls in; moving between bars and letting go snap.
  • A mask keeps rolling digits inside room above and below the line, so none is cut off mid-roll.
  • EarnedLine holds one prebuilt paragraph per bar and draws in the hero's canvas. Scrubbing swaps which one shows, and a tint gives it the theme's colours.
  • All 20 slots are recorded into one Skia picture per frame (one mapper), each glyph at its own alpha.

08Glass

Aave's glass as a native view, drawn in the same frame as its children, plus a finger light and stretch shared by every glass surface.

  1. Copy the window under the glass with PixelCopy as it appears, while it's still see-through, so the glass isn't in its own copy. The region is where layout puts the glass at full size, padded by 32 dp, and taken at half the screen's pixels (the copy is blurred anyway). A copy that fails while the surface is replaced gets one retry a frame later.
  2. Thin, then blur: the copy becomes a hardware bitmap in a RenderNode. An AGSL pass makes the background eat 1.5 dp into whatever stands out from it, then a RenderEffect blur runs (sigma = 0.57735 r + 0.5; a CSS blur is two sigmas).
  3. Bend with an AGSL RuntimeShader drawn straight to the window: a rounded-rect distance field gives each pixel its depth from the rim. Inside the lip, the input moves towards the middle by the cube of how close it is to the rim, leaned towards the corners, thinned along the rim and softened across it. Red and blue split by a share of the bend, a faint reflection lights the lip, and the rim brightens only where it catches something brighter than the backdrop. The shader cuts the rounded edge itself, so no clip layer is needed.
  4. Re-bend only when the glass moves: the bend reads the glass's matrix to the window (transformMatrixToGlobal), so a scale-in or stretch redoes only the bend, never the copy or the blur.
  5. Cache the rest: a look with a blurred shadow or glow is rasterized once into GPU layers, so a window redraw (Skia redraws the chart every scrub frame) replays a texture. A plain fill like the page draws straight.

The lens needs Android 14+. Older versions show the fill alone. The shadow shader needs 13+.

  1. Copy the window under the glass with drawHierarchy(afterScreenUpdates: false) on the next turn of the run loop, at one pixel a point, over where layout puts the glass, padded by its reach.
  2. Thin and blur once on the GPU on a .userInteractive queue: Core Image on a Metal CIContext, into a texture the GPU keeps.
  3. Bend with a CIKernel that matches the AGSL shader term for term. The shared constants are checked by lensConstants.test.ts, which fails if the two drift.
  4. A CADisplayLink reads the glass's placement in the window each frame (scale-in and stretch are transforms on views above it, which tell it nothing) and re-bends into a CAMetalLayer only when it changed.
  5. The glass's layers sit in a background view under the React children, which Fabric mounts one index higher.

10Theme switch

theme.tsx: dark is Aave's Future screen, light is Aave's light balance screen.

A switch flips two shared values on the UI thread, with no render: themeModeValue for Skia and viewThemeModeValue for views. Glass is different: each glass view gets both looks as props, and setGlassThemeMode() (called with the switch) makes one native call that sets every live glass to the other look. The page gradient is a vertical-fill glass view, so it switches the same way; icons switch their colours through animated props. Nothing is drawn twice per theme any more.

The views switch 3 frames after Skia. Skia on Android presents through a TextureView, 3–4 frames behind the views around it (measured on the Redmi with screenrecord). A fade to hide the variation redrew the chart too slowly to keep up.

The choice is saved in MMKV. On Android, SystemNightMode (an inline Kotlin module plus a config plugin) saves the scheme for the system, so the next launch's splash and system bars come up in it. It's applied only when the app goes to the background, because it re-lays out every view. iOS takes its scheme from Appearance before the first frame.

Primitives

The few pieces everything else is built from. They exist so that a press, a colour or a repaint never has to wait on the JS thread.

usePressGesture

src/ui/usePressGesture.tsUIJS

The tap every pressable in the app uses. Press state starts on the UI thread at touch-down, so the feedback never waits for a busy JS thread; onPress runs on JS once the tap lands. It returns { gesture, isPressed, targetProps }: render the target inside a GestureDetector and spread targetProps on it.

How it works
  1. A Gesture Handler v3 useTapGesture with maxDistance: 10: past that the finger is scrolling, and the press cancels. maxDuration is a day, not infinity, because iOS converts it to int64 nanoseconds and MAX_SAFE_INTEGER overflows.
  2. onBegin sets the isPressed shared value. onDeactivate, if the tap wasn't cancelled, fires pressHaptic and the optional onPressUI worklet on the UI thread, then hops to JS. onFinalize clears isPressed.
  3. onPress and enabled are read from a ref refreshed in a layout effect. An inline callback changes every render, and a changed closure makes Reanimated re-register the gesture's handler, so the gesture never sees it directly. The stable runPress also checks enabled again, because a tap queued on the UI thread can land after the button turned disabled.
  4. targetProps makes the view accessible with one activate action (a plain view has no click) that does what a tap does, and claims the JS responder so an enclosing pressable doesn't fire on the same touch.

PressableOpacity · PressableScale

src/ui/Pressable.tsxUI

The two looks of a press, built on usePressGesture. Both wrap their children in an Animated.View whose style is a worklet of isPressed, eased over 250 ms on bezier(0.25, 0.1, 0.25, 1).

Text

src/ui/Text.tsxJSUI

The app's only text component. It picks the cheapest renderer that can draw what it's given, and recolours on the UI thread when it has a theme colour.

How it works
  1. A single run of plain strings and numbers goes to react-native-plain-text's native label, which is cheaper than RN <Text>. Nested text (checked through unstable_TextAncestorContext), mixed children and fit fall back to RN <Text>; fit sets adjustsFontSizeToFit on one line.
  2. With a color token, it registers one animated hook: PlainText gets an animated color prop (PlainText reads its native colour from style.color and leaves it out of its types), RN text gets an animated style. Both read useViewColor, so a theme switch recolours them with no render.
  3. Without a colour it registers nothing. Toggling color between set and unset remounts it, because the hook count changes.
  4. unstable_lineHeightClippingCompat makes PlainText clip under a short line height like RN <Text>, which every layout here was measured against.

Icon

src/ui/Icon.tsx · icons/svg-sourceUI

A glyph from the app's icon font. bun run generate:icons builds it with nano-icons from the SVGs in icons/svg-source and writes a glyph map. size is the SVG's viewBox height in points. A two-tone icon (the book, the document) takes one colour token per layer, in the SVG's order.

How it works
  1. On render it builds both themes' colour arrays up front (byMode), already run through processColor, one entry per layer.
  2. An animated prop sets the native view's per-layer colors from viewThemeModeValue, so a theme switch needs no render.
  3. It mounts with the current mode's colours through the plain color prop, because the icon set renders from color and ignores the animated colors until the mode next changes.
  4. Icons are decorative and hidden from screen readers; the control around them carries the label.

Skeleton

src/ui/Skeleton.tsxUI

A grey box standing in for a value that's still loading: the theme's skeleton fill, no touches, and a 120 ms fade-out as it leaves, so it cross-fades with the value fading in. Used for the rate value, HeroSkeleton (two boxes as tall as the amount and the earned line) and ChartSkeleton.

DamageBoundary

src/ui/damage/DamageBoundary.tsx · DamageBoundaryModule.ktNative

Keeps something that animates from repainting the whole window on Android. React Native's views don't clip their children, so HWUI can't bound what a changed view damages: one spring on a pressed button repaints everything, the chart's Skia canvas included.

How it works
  1. On Android it renders an inline Expo view, DamageBoundaryView. A plain Android parent clips its child to the child's bounds, which also bounds the damage of everything inside. Its onLayout does nothing, so React Native keeps placing the child.
  2. Inside sits one child view grown by outset on every side (a negative margin with the same padding), so the clip reaches past whatever draws outside the content: a shadow, a press that grows the view, the stretch of glass.
  3. On iOS it's a plain View: Core Animation already composites each layer by its own bounds.

How it works
  1. One pan from touch-down drives everything, so the light and stretch follow the finger even past the edge. onBegin presses the glass and starts the bounce; onUpdate moves the light; onFinalize releases both.
  2. It presses if the finger is let go over the button (within the 8 pt slop). It can't use !event.canceled: a tap that never moves fails the pan, and v3 reports a failed pan as cancelled.
  3. The bounce grows to 1.06× over 110 ms. On release it first finishes the grow if the tap was shorter than that, then springs back with a small overshoot (stiffness 420, damping 22), so every tap gets the whole up and down.
  4. glassStyle lets a caller animate the outer size: HelpResetButton widens it into a pill.

SlidingTabs

src/ui/SlidingTabs.tsxUIJS

One component, two looks. "pills" is the range picker under the chart (6M 1Y 10Y 30Y). "segmented" is the track with a sliding thumb in the Add Money tray (One-off / Monthly) and the About tray's Formula / Value switch.

How it works
  1. The selection as drawn is a shared value, shownIndex. A tap on a new tab sets it in onPressUI, on the UI thread as the tap lands, ahead of the render onSelect causes. An effect copies selectedId into it for selections that didn't come from a tap.
  2. Segmented: a thumb under the labels springs to thumbIndex × tabWidth (320 ms, damping ratio 0.85). Tab width is rounded to whole pixels on layout, so the thumb's edges stay sharp at every tab, not just the first.
  3. Pills: the fill doesn't slide. Each tab has its own PillFill; the new one grows in from 0.75× and settles without passing full size (220 ms, critically damped), while the old one fades in place in 120 ms. Pills are 47 × 32.6 pt, about Aave's label width plus 13 pt each side, and their labels stop growing at 1.3× font scale.
  4. The selected tab's label switches to foreground, the rest are tertiary.

ThemeModeIcon · ThemeToggle

src/ui/icons.tsx · src/SavingsScreen.tsxSkiaUI

The toggle at the top right is a GlassButton holding ThemeModeIcon: a moon in dark mode that swells, turns and loses its bite into a sun in light mode.

AaveGlassView

AaveGlassView.swift · AaveGlassLens.swift · AaveGlassView.ktNative

The native view behind GlassView, registered by AaveGlassModule on both platforms.

How it works
  1. Looks and themes. Both looks arrive as props. A static set of every live view lets setThemeMode reach them all. Expo sets every prop again on each update, so a view compares old and new looks and only marks itself stale on a real change. On Android the switch waits 3 frames to land with the views (Skia presents behind them); at launch it applies at once, so the first glass doesn't mount in the wrong theme.
  2. The body. iOS builds it from Core Animation layers: an even-odd masked shadow, a gradient fill, a shape-layer glow, a gradient sheen and a masked gradient rim, laid out with actions disabled. Android draws it in dispatchDraw: a runtime shader for the shadow (a logistic falloff close to a Gaussian, with alpha-only dither so a faint, wide shadow doesn't band in 8 bits), a gradient fill, a blurred cut-out for the glow.
  3. Caching. Only a look with a blur is worth a GPU texture. Android records it into a RenderNode (API 29+); iOS rasterizes the masks and glow. A plain fill like the page draws straight, without a screen-sized bitmap.
  4. The lens copies the window behind the glass once as it opens, thins and blurs it once, then bends it on the GPU wherever the glass is on screen (Android 14+ and iOS; older Android shows the fill). Section 08 walks both pipelines.

useGlassTouch · useGlassTouchObserver

The stretch
  1. The first 6 pt past an edge only shifts the whole surface 1 pt towards the finger (the lead).
  2. Beyond that the near edge follows a rubber band, limit · tanh(d / (6 · limit)): about 1 pt per 6 pt of drag at first, then ever less, never past the limit. The surface also leans up to 2 pt more towards the drag.
  3. The edge towards the finger moves out and the one behind stays put (translate by half the stretch, scale by the rest). The other axis narrows by 0.3 of the growth, as if the glass kept its volume.
  4. reach goes 0 → 1 as the stretch nears 85% of its limit; the light dims by up to 90% with it, so it leaves the glass with the finger.

How it works
  1. Placing. BarChart

How it works
  1. The frame. react-native 0.88.0~1.3k lines Why RN builds from source: several hunks are native.
  • Context propagation (the Fabric renderer, dev, prod and profiling builds): when a context changes, React walks down to find what reads it. A nested provider of the same context now stops that walk for that context, since nothing under it can see the outer value.
  • Mounting differ: children that are the same shadow node in the old and new tree are left out before diffing, since they can't produce mutations (the change proposed upstream in facebook/react-native#59242, always on here; off on Android while its mounting layer isn't ready).
  • iOS views: RCTViewComponentView stops re-drawing its layer when only its position or opacity changed. The layer only needs the opacity for filter, and a move only matters for the pointer hover shape.
  • Feature flags, both platforms: static view configs instead of asking native (the native lookup cost about 1 s on the first launch after an install or update). preventShadowTreeCommitExhaustion, which Reanimated's no-commit-pausing mode relies on. Shadow tree revisions destroyed off the JS thread. On Android, prepared text layout and text measurement optimisations (a paragraph is measured once and the view paints that layout).
  • Hermes: the startup heap starts at 64 MB instead of 32, so the old generation, sized for live data at 50% occupancy, stops collecting about ten times while startup grows it.
  • Android back: the back callback is registered on every API level. An app that opts into predictive back on Android 13–15 never gets onBackPressed, so without it every press sent the app to the background.
react-native-reanimated 4.7.1360 lines
  • Theme switch without commits (Android): a numeric color on a PlainText label now goes down Reanimated's synchronous path, set on the native view directly, instead of a shadow tree commit (clone, layout, mount). A theme switch recolours every label at once, so this is most of its cost. RN <Text> can't do this: its colour lives in the shadow tree's attributed string. The C++ serializer and the Kotlin parser learn the new prop.
  • Null props: a prop reset to null goes through a commit, because the synchronous buffers read numbers and threw on it.
  • Bad writes: a shared value write that isn't an animation throws on the UI runtime, which is fatal in release. Release now drops it and reports; dev still throws.
  • Layout animations end one frame later, so one that settles between two of the legacy proxy's transaction pulls doesn't lose its last frame (unless a new animation has taken the view by then).
react-native-skia 3.8.1390 lines
  • Pipeline cache on disk: Dawn's blob cache saved through its device callbacks, written off the calling thread and fsynced before the rename. Without it every launch recompiled every GPU pipeline: about 2.8 s of CPU on the Redmi. Entries are keyed by adapter, driver and Dawn version and hold their full key, so a stale entry is a miss, never a wrong shader. On Android it lives in no_backup, which storage pressure never empties (a miss costs the Redmi about 1.5 s).
  • GPU memory: Graphite's budget of unused resources is lowered. Every render thread keeps a recorder with its own budget, so it counts once per thread: at 64 MB each, two canvases held about 340 MB on the Redmi.
  • MSAA off: with multisampling, every render pass after a frame's first reloaded the whole canvas (about 570 ms of main-thread presents in one profile). This is why the chart draws rounded rects and circles, which Graphite draws analytically, instead of paths, which it rasterizes on the CPU.
  • Surface capabilities asked once per process: every window reports the same, and asking cost about 16 ms of main thread per canvas attach on the Redmi.
  • A crash: a JSI call with no arguments let the compiler hoist a read of the null argument list above the count check (SIGSEGV).
react-native-worklets 0.13.035 linesThe TurboModule spec is required inside the "React Native runtime" branch instead of imported at the top. With Expo's tree shaking, a module with side effects is never inlined, so the import evaluated the spec (and NativeModules) on the UI runtime in Bundle Mode.
react-native-gesture-handler 3.4.062 lines
  • Android: a gesture that activates on touch-up (a tap) no longer sends a cancel to the JS responder. RN's root has already ended that touch, so the cancel landed on nothing.
  • iOS: RNGestureHandlerButton mounts children by sibling, not by index. Its underlay layer sits at index 0, so a child mounted after the first layout landed one slot too low, under the sibling it should cover.

@lodev09/react-native-true-sheet 3.10.1~3k lines The biggest patch. This app relies on these parts:
  • keepMounted (this app's): renders the content before the first present and keeps it after a dismiss, so presenting is only the native animation. It's derived in the render that turns it on, so it costs one commit rather than a second one after it. The Add Money tray uses it.
  • No visible grow on open: a present waits until the auto detent has a measured height, since a first present shares its commit with the mount and would otherwise open at the header's height and grow a beat later. A 500 ms escape presents anyway. On iOS the content is seeded with the window's width before the first layout for the same reason.
  • Present and dismiss races: a dismiss issued mid-present waits for the present to finish (UIKit drops it), a present issued mid-dismiss waits for the dismiss, a present on a controller mid-transition waits it out, and a superseded present resolves instead of leaving JS waiting forever.
  • View recycling: a pooled sheet view no longer hands its measured heights and presentation state to the next sheet that mounts.
  • Touches (Android): a closed sheet's screen-sized host no longer takes the touches of whatever it covers.
The rest serves features this app doesn't use yet: a colour-animated dim that matches the sheet, a 1 pt outline, a faster detent morph (resizeSpeed), capped detents, footer-pinned "tray" content and per-frame morph events.
react-native-plain-text 0.9.3~1.6k lines Android only, all about measuring labels faster:
  • A single-line fast path: text that fits one line skips TextView.measure and the StaticLayout it builds. Its width comes from the shaped text and its height from the line height.
  • A measure cache saved across launches, so a cold start skips measuring labels it measured last time. A content provider starts loading the file before Application.onCreate, and a measure never waits for it. The file is thrown out whole if anything that could change a size differs: app build, OS build, fonts, density, font scale, Bold Text or locales. Only bundled fonts and code points below U+2000 are saved, since emoji and CJK fonts update outside the app.
  • Correctness: a size measured with a fallback font (before a runtime font registers) isn't cached, a Bold Text or locale change clears the cache, and the answer is clamped to Yoga's bounds. The Kotlin measure answers in whole pixels, so a 220.691 pt width came back as 220.364 and Fabric logged "invalid measurement" on every miss.
react-native-nano-icons 1.0.040 lines
  • The native view is assumed present instead of asked for. It's codegen'd and always linked, and asking cost about 12 ms of JS at startup.
  • Android: a one-layer icon reports no overlapping rendering, so fading it doesn't allocate an offscreen layer every frame. Two-tone icons keep the layer so their layers don't show through each other.
